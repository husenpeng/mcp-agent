# Work 桥接：第三方 Work App 检测与任务直连 — 完整技术方案

配套交互原型：[prototype.html](prototype.html)（浏览器直接打开，含全部状态机与边界场景演示）。

## 1. 目标与非目标

**目标**

1. 检测本机所有已安装的 work app（Claude Code / Codex / Qwen Code / Gemini CLI / 豆包工作台 / 通义等），给出每个 app 的可用等级。
2. 在 Tomato GUI 内直接把任务派给指定 app 执行，流式回传进度与结果；`auto` 模式按 autoswap 式选路自动挑后端并兜底。
3. 全部边界情况有明确行为与归属（§8 矩阵）。

**非目标**

- 不新造执行环：委派一律走既有 `ctx.subagents` 提供方注册表（[subagent 子系统](../docs/subsystems/subagent.zh.md)）。
- 不做豆包/通义的云端 API 逆向；封闭桌面产品只走受权限管控的 GUI 自动化（CUA），且明确标注 best-effort。
- 不把外部 app 的推理、工具流量、stderr 灌进父 Session（沿用现有提供方的隔离约定）。

## 3. 应用检测

### 3.1 清单模型

每个 app 一条 `WorkAppRecord`（branded id，非裸 string）：

```ts
interface WorkAppRecord {
  id: WorkAppId                    // 'claude-code' | 'codex' | 'qwen-code' | 'doubao-work' | ...
  displayName: string              // 本地化展示名
  install: {
    kind: 'desktop' | 'cli' | 'both' | 'absent'
    paths: readonly string[]       // 多副本全部保留（检测不折叠，展示折叠）
    bundleId?: string              // com.bot.pc.doubao 等
    version?: string
  }
  adapters: readonly AdapterProbe[] // 每档适配的探测结果，见 3.3
  auth: 'ok' | 'missing' | 'expired' | 'unknown'
  status: WorkAppStatus            // 由 adapters+auth 推导，唯一真源
  lastSeenAt: number
}
type WorkAppStatus =
  | 'ready'          // 至少一档程序化适配可用且已登录
  | 'gui-only'       // 只有 CUA 档可用（豆包/通义桌面）
  | 'not-logged-in'  // 已安装、适配在、登录缺失
  | 'outdated'       // 版本低于适配最低要求
  | 'absent'         // 未安装
```

### 3.2 检测来源（按平台）

| 平台 | 桌面 app | CLI |
|---|---|---|
| macOS | `/Applications` + `~/Applications` 枚举，NSWorkspace/NSBundle 读 bundle id、`CFBundleShortVersionString`、图标（复用 native-command 的 JXA 模式） | PATH 逐目录探测 + `--version` 探针；`~/.claude`、`~/.codex/auth.json`、`~/.qwen` 判登录态 |
| Windows | 注册表 Uninstall 键 + Start Menu 快捷方式 | `where.exe` + 版本探针；凭据文件同 macOS 逻辑 |
| Linux | XDG `.desktop` 枚举 | PATH 探测 + 版本探针 |

已知 app 注册表（bundle id / CLI 名 / 探针命令 / 最低版本 / 适配档位）是**数据不是代码分支**：新增一个 app = 加一条注册表行 + 可选适配配置，不改检测逻辑。未知 app 不猜测能力，只报 `absent`/不收录。

### 3.3 能力探测（每档独立）

| 档 | 探测内容 | 失败降级 |
|---|---|---|
| A 原生协议 | SDK/app-server 载荷存在、平台受支持 | 降到 B/C |
| B ACP | CLI 存在且支持 ACP 启动参数 | 降到 C |
| C headless CLI | `claude -p` / `codex exec` / `qwen -p` 可非交互运行 | 降到 D |
| D CUA GUI | 桌面 app 在 + 辅助功能/录屏权限已授 | 报 `gui-only` 且标注权限缺失 |

探测全部**只读、限时**（单探针超时默认 5s，可配），不启动真实任务、不写任何 app 状态。登录探测只查凭据文件存在性与mtime，不验证 token 有效性（有效性在首次派发时由适配层报告，避免检测阶段触发刷新/弹窗）。

### 3.4 刷新策略

- 面板打开时全量扫描一次；之后按需刷新按钮 + 应用目录 fs watch（debounce 2s）。
- 扫描是后台 job，UI 先渲染缓存清单（storage-domain 持久化），扫描完成按 commit point 整体替换，不做逐条闪烁更新。
- 任务派发前对**目标 app** 做一次定向复检（版本/登录/进程），不复用全量缓存——缓存只用于展示。

## 4. 调用适配（五档）

| App | 首选 | 兜底链 | 说明 |
|---|---|---|---|
| Claude Code | A：`subagent-claude-code`（官方 SDK） | C：`claude -p` | 原生设置/登录是权威；凭据特征环境变量先清理再叠加显式 `env` |
| Codex | A：`subagent-codex`（app-server） | C：`codex exec` | 平台锁定载荷，不回退宿主 CLI（沿用现有约定） |
| Qwen Code | B：`subagent-acp`（`qwen --experimental-acp`） | C：`qwen -p` | ACP 命令为注册表配置项，版本漂移时探测失败自动降 C |
| Gemini CLI | B：`subagent-acp` | C：headless | 同上 |
| 豆包工作台（桌面） | D：`work-bridge-cua` | 无 | 封闭产品，无公开程序化入口；best-effort，见 §8-G |
| 通义（桌面） | D：`work-bridge-cua` | 无 | 同上 |
| 任意 ACP agent | B：`subagent-acp` | — | 用户自定义 command/args，注册表加行即接入 |

**C 档（新包 `subagent-cli`）**：经 subprocess seam spawn headless CLI，stdin 传任务、stdout 按行解析语义事件（各 CLI 的 JSON 输出格式为注册表配置），stderr 只进 Host 日志。无人值守：任何交互式提问一律视为失败而非挂起。

**D 档（实验包 `work-bridge-cua`）**：经 `ctx.computerUse` 驱动桌面——定位 app 窗口 → 输入任务 → 观察完成信号 → 提取结果文本。每一步截图进任务时间线；权限缺失时 preflight 直接拒绝并给出授权指引，不半路弹窗。结果提取失败结算为 `unknown`（§8-G3），绝不编造答案。

## 5. 选路（autoswap 式编排）

单入口 `dispatch`，调用方（UI 或模型工具 `work_dispatch`）不感知下游协议：

```
dispatch(task, target, cwd)
  1 preflight   目标复检 + 适配档位 + 权限 + 工作区存在性 + 风险分级
                → PreflightResult{app, adapter, risks[], needsApproval}
  2 approval    高风险（写操作/ bypass 权限 / CUA 控制桌面）→ 审批卡，人批准才继续
  3 route       target=auto：按「能力匹配 ∧ 已登录 ∧ 版本达标 ∧ 并发未满 ∧ 用户允许」
                全真才选该 app；任一不满足按注册表优先级顺延，并记录 fallbackReason
  4 execute     委派 ctx.subagents 对应提供方；语义更新流式进任务时间线
  5 settle      success | error(分类诊断) | aborted | unknown
                ExecutionRoute{app, adapter, routeType: direct|fallback, fallbackReason?, steps[]}
```

**硬规则**

- 兜底最多一跳（A→C 或 B→C），禁止链式回退与回退环；D 档永不参与 auto 兜底（GUI 自动化副作用不可控，只能显式指定）。
- 写操作遇进程失联 → `unknown` + 人工决定，**不自动重试**（文件写入没有幂等 tx）。
- 每次选路结果（含放弃原因）写入 session event，UI 徽标与模型可见文本同源（model-visible ⟺ logged）。
- 选路优先级、并发上限、超时全部是 validated Config 字段，cordis.patch.yml 可改，无硬编码 tunable。

## 6. UI 规格（ui-work-bridge）

### 6.1 布局（对应原型）

```
┌──────────────────────────────────────────────────────────────┐
│ Work 桥接                                      [刷新] [设置]  │
├──────────────┬───────────────────────────────────────────────┤
│ 应用清单      │ 派发台                                         │
│ ┌──────────┐ │  任务输入（多行）                               │
│ │Claude Code│ │  目标: [auto ▾]  工作区: [当前 ▾]              │
│ │ ● 可直连  │ │  ── preflight 卡：路由/风险/预计耗时 ──         │
│ └──────────┘ │  [派发任务]                                    │
│ ┌──────────┐ ├───────────────────────────────────────────────┤
│ │豆包工作台 │ │ 任务时间线                                     │
│ │ ◐ 仅GUI  │ │  ┌ 任务卡：路由徽标 │ 流式步骤 │ 取消 ┐         │
│ └──────────┘ │  └ 结果 / 失败诊断 / unknown 决策条 ┘          │
└──────────────┴───────────────────────────────────────────────┘
```

### 6.2 状态机

**清单**：`cached → scanning → ready`；扫描失败保留缓存 + 顶部横幅（不白屏）。
**任务**：`draft → preflight → (approval) → running → settled{success|error|aborted|unknown}`；`running` 可取消；`unknown` 必须人工选择「标记失败 / 我去检查」才能关闭。

### 6.3 关键呈现规则

- 路由徽标四态：`直连`（绿）/ `已回退`（黄，hover 显示 fallbackReason）/ `GUI 自动化`（紫，常驻警示）/ `unknown`（红）。
- 状态点与 app 卡：ready 绿、gui-only 紫、not-logged-in 黄（卡内直接给「去登录」指引文案）、outdated 灰、absent 不显示但可在设置里看到完整注册表。
- CUA 任务卡常驻「正在控制你的桌面」横幅 + 实时截图缩略图；取消按钮永远可用。
- 全部文案走 typed dictionary + `t`（locale-owned，sentence case），无硬编码。
- 空态：无任何 app → 引导安装卡片（列出注册表支持的 app 与获取方式），不是空白。

### 6.4 接入点

- 面板：`ctx.slots.inject` 到工作区导航既有 slot；任务卡复用 conversation 事件渲染模式（raw events + 持久化 result metadata 推导，presenter 纯函数）。
- Host 侧：`@Remote` 方法 `workApps.list/refresh`、`workBridge.preflight/dispatch/cancel/resolveUnknown`；任务进度走既有 session event 流，不另造推送通道。

## 7. 交互时序（一次 auto 派发）

```
用户输入任务 → UI 调 preflight(auto)
  → 返回路由卡：选中 claude-code(A档)，风险=写文件，需审批
用户点「派发」→ 审批卡（列出将写入的 cwd 与权限档）→ 批准
  → dispatch → subagent-claude-code 启动 → 语义更新流式进时间线
  → SDK 报 query-start 失败（载荷缺失）
  → 选路记录 fallbackReason，一跳降到 C 档 claude -p
  → 任务卡徽标变「已回退」，时间线插入回退事件
  → CLI 成功 → success，结果 + ExecutionRoute 展开可查
```

模型侧同构：`work_dispatch` 工具返回任务名，完成通知带最终答案或安全诊断；父 Session 只存外部任务身份与终态（沿用 tool-subagent 约定）。

## 8. 边界情况矩阵

### A. 检测

| # | 情况 | 行为 | 归属 |
|---|---|---|---|
| A1 | 未安装任何 work app | 空态引导卡；`work_dispatch` 返回结构化「无可用后端」 | ui / bridge |
| A2 | 同一 app 多副本（/Applications + ~/Applications） | 检测保留全部路径，展示折叠为一条；派发用版本最高且登录态 ok 的副本 | detect |
| A3 | PATH 里 CLI 被 shadow（旧版本在前） | 探针报告实际命中路径与版本；outdated 时卡内提示冲突路径 | detect |
| A4 | 版本探针挂起/输出非预期 | 单探针 5s 超时，该档记 `probe-failed`，不阻塞其余档 | detect |
| A5 | 扫描期间 app 被卸载 | 派发前定向复检兜住；运行中任务不受影响（进程已 spawn） | bridge |
| A6 | 凭据文件在但 token 过期 | 检测报 ok（只读存在性）；首次派发由适配层报 auth 失败 → 状态翻 not-logged-in，不自动重试 | detect/adapter |
| A7 | 无权限读应用目录（受管设备） | 该平台来源记 `permission-denied`，其余来源继续；横幅说明 | detect |

### B. 登录与凭据

| # | 情况 | 行为 | 归属 |
|---|---|---|---|
| B1 | 未登录就派发 | preflight 拒绝，给「去登录」指引；不 spawn 进程 | bridge |
| B2 | 任务中途登录失效 | 适配层结算 error(auth)；不触发任何自动登录/弹窗 | adapter |
| B3 | 父进程环境含 API key | 沿用现有约定：凭据特征变量先清理，子进程 key 必须显式 `env` 配置 | adapter |
| B4 | 多账号 | 一期不支持账号切换；用 app 原生当前账号，卡内显示账号标识（只读） | bridge |

### C. 选路与派发

| # | 情况 | 行为 | 归属 |
|---|---|---|---|
| C1 | auto 无任一 ready app | 结构化失败，列出每个 app 的落选原因（可解释路径） | bridge |
| C2 | 指定 app 不可用 | 不静默换目标；报错并建议可用替代，由用户/模型显式重派 | bridge |
| C3 | 回退后再失败 | 结算 error，两跳诊断都进 ExecutionRoute；禁止第三跳 | bridge |
| C4 | 回退环（配置错误导致 A→B→A） | 路由记录 visited 集合，重复即终止 | bridge |
| C5 | 并发超限（默认每 app 2，可配） | 排队进任务时间线显示「等待槽位」；超队列上限拒绝 | bridge |
| C6 | cwd 不存在/无权限 | preflight 拒绝；不创建目录 | bridge |
| C7 | 任务文本为空/超字节上限 | schema 层拒绝（上限为 Config 字段） | tool/bridge |
| C8 | 高风险未审批 | 停在 approval 态；超时（可配）自动 aborted，不默认放行 | bridge |

### D. 执行

| # | 情况 | 行为 | 归属 |
|---|---|---|---|
| D1 | 子进程崩溃/被杀 | 结算 error(process)，带生命周期阶段与观测退出码；写操作无结果证据时升 unknown | adapter |
| D2 | CLI 弹交互式提问 | 无人值守：视为失败 error(interactive)，绝不挂起等输入 | adapter |
| D3 | 输出超上限/非 UTF-8 | 按完整结果施加字节上限（含包装），截断标注；非法字节替换并记诊断 | adapter |
| D4 | 流式断连（GUI 重连） | 任务状态以 Host session event 为权威；重连按 afterSeq 续帧，不重放执行 | client |
| D5 | 用户取消 | 本地取消在结果竞态中胜出 → aborted；managed-range 逐级终止（沿用 disposeGraceMs 约定） | adapter |
| D6 | Host 重启/插件卸载 | 运行中任务随 fiber dispose 逐级终止；重启后任务卡显示 interrupted 终态，不假装还在跑 | bridge |
| D7 | 外部 app 限流/配额耗尽 | 适配层归类 error(quota)；auto 模式**不**把 quota 失败当回退理由（换后端也烧同一份额度时误导），仅协议/载荷失败才回退 | bridge |
| D8 | 任务超时（可配，默认 15min） | 超时 → 取消流程 → aborted(timeout)；写操作同 D1 升 unknown 规则 | bridge |

### E. 结果与信任

| # | 情况 | 行为 | 归属 |
|---|---|---|---|
| E1 | 外部输出含指令性文本 | 一律当数据：结果进父会话时包裹外部内容标记，不作为指令执行（prompt-injection 边界） | bridge |
| E2 | 结果与任务无关/空答案 | 沿用 claude-code 约定：空白 result 不算 success | adapter |
| E3 | unknown 终态 | 任务卡红色决策条：「标记失败」或「我去检查」；选择前不允许关闭；决定写 session event | ui/bridge |
| E4 | 外部 app 改了工作区文件 | 结果附 diff 摘要开关（默认折叠）；diff 计算在 Host，不信任外部自报 | bridge |

### F. 平台与权限

| # | 情况 | 行为 | 归属 |
|---|---|---|---|
| F1 | macOS 辅助功能/录屏未授权（CUA） | preflight 拒绝 + 系统设置深链指引；授权后需手动复检 | cua |
| F2 | Windows UAC / 受管设备禁 spawn | 适配 probe 失败 → 该档不可用；错误文案区分「未安装」与「被策略阻止」 | detect |
| F3 | Linux 无桌面会话（headless 服务器） | D 档整体不可用；A/B/C 正常 | detect |
| F4 | 离线 | A/B/C 本地 CLI 仍可跑（取决于 app 自身联网需求）；preflight 标注「离线，外部 app 可能失败」；不阻止派发 | bridge |

### G. CUA 专属（豆包/通义）

| # | 情况 | 行为 | 归属 |
|---|---|---|---|
| G1 | 窗口找不到/app 未启动 | 允许启动 app（显式审批项）；启动后限时等窗口，超时 error(window) | cua |
| G2 | UI 改版导致定位失败 | 每步有超时与截图证据；失败结算 error(ui-changed)，提示注册表需更新 | cua |
| G3 | 无法判断任务是否完成 | 结算 unknown（绝不把「看起来像答案」的屏幕文本当 success 而不标注置信度）；结果卡强制显示「GUI 提取，未验证」 | cua |
| G4 | 执行中用户动了鼠标键盘 | 检测到前台输入冲突 → 暂停 + 横幅「检测到人工操作」，用户选择继续/取消 | cua |
| G5 | app 内弹出登录/付费墙 | 截图 + error(auth/paywall)；不代用户登录、不代付费 | cua |
| G6 | 豆包后续开放程序化入口 | 注册表加 A/B 档行即升级，D 档自动退为兜底；UI 无需改 | 注册表 |

## 9. 安全不变量

1. 平台不 dial 外部 app 的网络端口；一切调用是本机 spawn 或本机 GUI 控制。
2. 凭据不下发：子进程环境先清理凭据特征变量；CUA 不读取、不传输 app 凭据文件内容。
3. 路径 jail：任务 cwd 必须是用户显式选择的工作区；CUA 操作范围限目标 app 窗口。
4. 审批在做出决定的操作里强制执行（executor 层拒绝未审批派发），不靠 UI 隐藏按钮。
5. 外部内容一律数据化（E1）；审计：每次派发/回退/审批/unknown 决定都是 session event。
