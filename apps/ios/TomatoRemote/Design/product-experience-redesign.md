# TomatoRemote 产品动线与视觉重构方案

## 1. 产品定位

TomatoRemote 不是单纯的远程聊天窗口，而是一个随身 Agent 工作台：

- **总览**：知道今天完成了什么、什么仍在执行、什么需要自己处理。
- **执行**：随时发起或继续 Mac 会话、本机会话、智能体任务和群聊协作。
- **监督**：查看进度、回答审批、暂停或继续任务、定位异常。
- **回看**：读取回答、工具过程、交付文件、运行记录与定时投递。
- **校准**：管理个人记忆、模型、能力、账号、Host 与诊断信息。

设计原则：**结果优先于技术信息，待处理优先于历史，主任务优先于功能入口，内容优先于卡片装饰。**

## 2. 当前功能地图

| 区域 | 已有能力 | 主要对象 | 核心后续动作 |

| 能力市场 | 插件、Skill、MCP 的查看、启停、添加与删除 | Agent 能力 | 增强当前手机 Agent |

## 3. 截图与代码审计结论

### 信息架构

1. 首页导航名叫“记忆”，实际主体是今日回顾、目标和待办，名称与心智模型不一致。
2. 个人记忆、当前目标和今日英雄卡同时争夺首屏，待处理事项却可能被推到下方。
3. “今日回顾”同时作为英雄卡 eyebrow 与下方分组标题，重复且层级不清。
4. 会话页同时展示最近完成与项目文件夹，功能有价值，但视觉上同权重排列，重复感强。
5. 记忆待确认与生效中两区外观几乎一致，用户不能快速识别“哪里需要我行动”。

### 视觉与交互

1. 浅色页面与卡片都接近纯白，边框、圆角和阴影被迫承担过多层级表达。
2. 首页多个 elevated 卡片连续出现，长目标文本缺少摘要约束，首屏信息密度不稳定。
3. 会话、机器人、群聊卡片的圆角、边框和运行态底色规则不同，缺少统一行解剖。
4. 对话页状态条与正文 live row 重复，助手竖向强调线过长，工具、回答和交付物争抢注意力。
5. 浮动导航展开时没有足够的前景/背景分离，选中态品牌色面积偏大，菜单压迫正文。
6. Tomato Phone 仍有独立卡片尺度与 composer 结构，虽然颜色已统一，视觉语言还未完全统一。

## 4. 目标信息架构

### 顶层导航

1. **今天**：默认页。只回答“现在要关注什么”。
2. **会话**：Mac 上的单 Agent 工作。搜索、发起、继续与回看。
3. **Tomato Phone**：手机上的个人 Agent 与能力市场。
4. **智能体**：可重复使用的机器人及其运行。
5. **群聊**：多个智能体共同完成的协作任务。
6. **账号**：人的身份、记忆、设备、Host 与诊断。

个人记忆仍可从首页进入，但账号是其稳定归属；不增加新的顶层标签。

### 页面层级

- **L0 总览层**：今天、会话、Tomato Phone、智能体、群聊、账号。
- **L1 工作层**：Mac 对话、手机对话、智能体详情、群聊详情。
- **L2 任务层**：工具详情、进度、模型、权限、记忆详情、投递记录、日志。
- **L3 系统层**：文件/图片全屏预览、相机、系统分享与权限弹窗。

浮动标签球只出现在 L0；L1 进入专注任务后隐藏，通过标准返回回到来源。

## 5. 核心产品动线

### A. 每日检查与收尾

启动 / 回到前台 → 生物识别 → 今天 → 优先处理等待请求 → 查看进行中目标 → 扫读今日完成与未完成 → 进入相关会话或定时任务 → 返回今天确认状态。

规则：有待处理时它必须在回顾之前；无待处理时回顾承担首屏主视觉；目标文本列表只展示摘要，完整执行过程进会话。

### B. Mac 单 Agent 工作

会话 → 搜索或按项目定位 → 新建 / 继续会话 → 输入文字、语音、照片或文档 → 按需选模型与权限 → 观察进度 / 回答审批 → 阅读回答与工具摘要 → 打开交付物 → 返回最近完成或今天。

规则：主路径不出现技术标识；项目、模型、工具参数、token 等按需披露；运行状态在列表与对话内使用同一套语义。

### C. 手机个人 Agent

Tomato Phone → 必要时飞书登录 → 新会话或历史会话 → 输入任务 → 工具审批 → 获得回答 → 根据建议安装能力，或进入能力市场主动配置 → 回到对话继续。

规则：对话是主任务，能力市场是配置支线；切换市场不清空草稿与当前会话；安装完成后能回到原任务。

### D. 多智能体协作

智能体 → 查看状态与目标 → 新建 / 启动 / 中断 → 查看运行记录；或群聊 → 选择至少两个成员 → 描述共同目标 → 查看委派与回复 → 处理熔断或审批 → 回看结果。

规则：机器人状态与群聊状态使用相同的状态容器；运行记录最终都回到统一对话阅读器。

### E. 记忆校准

今天 / 账号 → 个人记忆 → 待确认优先 → 打开详情阅读完整内容 → 确认或删除 → 查看生效记忆 → 从本机观察提交候选。

规则：列表只保留内容、范围、状态和入口；entity/key 等技术信息仅在详情出现；破坏性操作有确认与取消。

## 6. 视觉方向：Warm Tomato Workspace

### 关键词

**温暖、克制、清晰、可信赖、轻量专业。** 不做营销型大红界面，也不把所有信息装进浮夸玻璃卡。

### 色彩

- 页面：`TomatoSurface.page`，暖灰底，托出白色工作面。
- 卡片：`TomatoSurface.card`；卡片内部：`TomatoSurface.variant/subtle`。
- 主品牌：番茄红只用于主操作、当前运行、待处理与选中态。
- 状态：成功 / 警告 / 错误 / 信息统一使用 `TomatoContainer` 成对前景与底色。
- 文本：主信息 `labelPrimary`，摘要 `labelSecondary`，元数据 `labelCaption`；`labelDimmed` 只用于装饰。

### 表面与层级

- 普通列表卡：单层填充 + `TomatoLine.hairline`，不使用阴影。
- 独立重点卡：允许 `flat/raised` 一级阴影；同一屏最多一个 hero。
- 待处理 / 当前运行：品牌或状态浅底 + 图标 + 文案，不只靠颜色。
- 导航与 composer：功能层可使用材质；正文与列表不使用玻璃。
- 圆角收敛：chip 8、control 14–16、list card 18–20、hero 28；避免所有容器都 24–32。

### 字体与密度

- 页面不恢复左上角大标题；分区标题用 `headline/subheadline` 的语义层级。
- 主标题 `.body/.headline`，摘要 `.subheadline`，元数据 `.caption`。
- 首页回顾标题最多三行，目标摘要最多三行；完整内容进入详情。
- 常规列表垂直内边距 10–12，区块间距 16–20，页面左右边距 16–20。
- 所有点击目标至少 44pt，信息文本不使用低对比度装饰色。

### 统一行解剖

`leading 状态/类型图标 → 主标题 + 状态 → 一行摘要 → 元数据/时间 → 下钻指示`

- leading 图标只表达对象类型，运行状态由 StatusPill 表达。
- 同屏相同对象保持相同槽位，数字右对齐并使用等宽数字。
- 最近完成弱化容器，项目文件夹保留分组结构，避免两个区域都像重点推荐。

## 7. 本轮实现范围

1. 将首页导航命名为“今天”，重排待处理、回顾、目标、列表与记忆入口。
2. 统一顶层页面背景、列表卡、按钮、状态、空态和分区标题。
3. 收敛首页 hero 与目标卡，减少重复标题和过度阴影。
4. 重构会话、智能体、群聊、记忆和账号卡片的槽位与层级。
5. 优化浮动导航的选中态、背景分离和菜单尺寸。
6. 收敛 Mac 对话与 composer；统一 Tomato Phone 的表面、间距和气泡语言。
7. 构建并用 Mock Host 检查浅色、深色和核心页面截图；保持现有功能与稳定 accessibilityIdentifier。

## 8. 最终验证

- 最终源码在 iPhone 17 / iOS 27.0 模拟器上构建成功。
- `TomatoRemoteTests`：132 项单元测试通过，0 失败。
- `TomatoRemoteUITests`：使用当前预览 Mock 可覆盖的 16 项核心界面测试通过，0 失败；覆盖导航、会话打开、最近完成、对话消息、输入框、记忆、首页与交付物。
- 已逐张检查首页、会话、Mac 对话、个人记忆、展开导航、Tomato Phone、智能体、群聊和账号页，并检查首页深色模式。
- 界面测试仅覆盖预览 Mock 提供的数据路径，不等同于真实 Host 的完整设备端到端验收；测试记录见 `.derived/unit-tests.log` 与 `.derived/ui-tests-mock.log`。
