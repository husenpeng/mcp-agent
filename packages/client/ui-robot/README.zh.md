# Robot UI

[English](README.md) | 中文

## 概述

`@tomato/client-ui-robot` 是 Tomato Rbot 的浏览器插件。它注册 `robots` 主面板，在该面板打开时侧边栏行下嵌套机器人名册，默认展示机器人卡片网格与模板，并通过三步创建向导或带内置 `robot-creation` 技能的会话创建机器人。每次运行通过 `SessionProvider` 绑定到自己的 Session 并渲染成对话：运行栏旁是 Markdown 回答、折叠的工具动作，以及一个负责开始、纠正或继续运行的输入框。编辑器编辑四项基础字段与高级默认值。注册表状态与调用都经 `ctx.robotRuns`，插件本身不持有传输状态。

## 使用本包

在与 `@tomato/api-robot-controller` 及 `@tomato/experimental-robot` provider 一同装配的浏览器组合中挂载本插件。它需要 `slots`、`locale`、`layout`、`robotRuns`、`sessions` 与 `uiWorkspace`。

创建是三步向导：每次运行要做什么、名称与一句话描述、成功标准与草稿预览。第一步给出部署领域的示例任务，并要求真实回答；名称不能为空且不能与既有 robot 重名；成功标准可以留空。预览会说明 robot 的工作目录（可通过文件夹选择器更改），以及其余高级项都使用通用默认值；最后一步就地发布规格并实例化，因此只有名称与任务目标必填。向导不会发布 [`emptyRobotSpec()`](../../experimental/robot/src/spec.ts) 里的占位名称或占位任务；未完成的草稿会退回需要回答的那一步，provider 拒绝时也停留在向导内并显示原因。

编辑既有 robot 时打开规格编辑器：基础页重复同样四项字段，其余区块留在「高级配置」并使用默认值。两个标签页共用同一份草稿，若 provider 的 issue 落在基础路径之外，编辑器会自动切到高级页。高级列表字段是 `robot.capabilities` 与注册表提供的选择器，同时保留自由输入以填写本地没有来源的值。技能、MCP 服务器与工作区根目录改为弹出层，而不是下拉菜单：技能列表显示每个技能的来源文件夹，MCP 列表列出部署已配置的服务器，工作区根目录额外提供「浏览文件夹…」，在 browse 部署里复用 `uiWorkspace.listDirectory`，在 native 部署里复用 `uiWorkspace.pickDirectory`。其余列表字段——工具、凭据引用、调用方、数据等级、意图、对等机器人——保留内联菜单。规格未声明根目录的既有 robot 会以页面正在查看的工作区目录起步，因此保存后的 robot 总会写明一个可检查的工作目录；招聘没有根目录的模板时会传入同一个目录。来源为空时显示弹出层的空状态与自由输入，并说明该值的出处。

只有访问快照允许 `session/create` 时才显示会话创建。它通过 `uiWorkspace.startSession` 发送一句简短的创建请求，让会话像用户自己提出需求一样开始；内置 `robot-creation` 技能随后一次只问一个问题，确认草稿后调用 `robot_create`。创建成功后，该工具调用在对话里渲染成独立的一行，显示 robot 名称与「打开机器人」按钮；点击会选中该 robot 并打开本面板。该行读取工具记录的展示元数据，重新打开历史会话也能保留这个入口。页面可从侧栏图标或 roster 行进入；点击行会打开 robot 页面并选中该 robot。

未选中 robot 时，页面显示卡片网格：搜索框匹配名称、描述和模板分类；「全部 / 运行中 / 空闲」筛选；用户的 robot 卡片显示状态、描述和运行次数；随后是已注册模板。选择「运行中」时隐藏模板。模板卡片上的加号按钮以当前语言调用 `hire` 并打开新 robot；聘用失败时，在网格下方显示错误信息。模板文案的语言回退规则与 Host 发布聘用时相同。卡片头像按 robot 首个可识别技能绘制角色图形——品牌、达人、素材，或某个平台的选品/数据洞察组合——其他 robot 回退到名称首字。

运行区分左右两栏。左侧运行栏显示 robot 的头像、名称与运行中/空闲状态，下面是它的运行记录；每条记录带业务状态标签——包括暂停中的 `waiting`——以及已用时间或总用时，运行栏底部说明当前运行未结束时为什么不能开始下一次运行。右栏是这段对话：顶栏给出运行状态、开始时间、用时、步数与失败数，以及「打断」「结束运行」和技术详情开关；指令以用户消息呈现；连续的工具动作折叠成一个「过程」区块，运行进行中默认展开、结束之后保持折叠；回答由该 run Session 的 Chat 节点按 Markdown 渲染；结尾是结果行或失败信息。整个流程只有一个输入框：没有运行在进行时开始新的运行，运行进行中把纠正发进这次运行，暂停后同一个输入框改为继续，页面因此不再另设一个启动输入。对话经 `ctx.uiConversation.binding(sessionId).target('chat')` 读取该 Session 已注册的 Chat 快照；技术详情开关在过程行里展开工具名与原始参数，不需要第二个视图。页面只在 run 被选中期间以 `robotRun` 引用源保留该 Session，并在卸载时释放。如果该 Session 已从客户端会话目录中移除（Agent 结束，Host 收回该行），页面先拉取一次该目录再重试保留；仍然无法解析时，右栏照常显示运行状态、指令与结果，只在进展列表说明会话记录不可用，而不是让页面失败。

<a id="dev-note"></a>
## 开发备注

页面选择 store 投影为 `useRobotPage`，其中包括卡片网格的搜索文本、筛选状态和 `create` 视图；store 实例同时提供 PropsStore 的 `actions`。创建向导把草稿与当前步骤保存在组件状态里，离开即丢弃草稿，不会发布任何内容。注册表数据是 `robotRuns` 快照，由整份 `robot.watch` 帧替换，名册与运行状态因此无需轮询即可收敛。工作区浏览器会排除摘要携带 `robotRun` 投影的 Session，该投影由 runtime 从 run 的日志记录写入。

<a id="model-experience"></a>
## 模型体验

### 运行使命

#### 模型看到什么

页面本身不添加任何内容。robot run 的模型看到的是 `@tomato/experimental-robot-runtime` 由规格中的使命、成功标准、停止条件与输出验收组装的 `robot:mission` 系统提示区段。

#### Token 影响

每个 run 一个提示区段，大小由编辑器写入的规格文本决定；页面自身不增加 token。

#### KV 缓存影响

同一修订内该区段稳定。发布并重绑新修订会改变提示前缀，下一次 run 从新的缓存开始。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- 「过程」区块折叠 Chat 目标的节点，因此必须挂载 `@tomato/client-ui-chat`；时间线只读取它物化出的节点，不拥有这些定义。
- 技术详情开关保存在浏览器存储而非 profile 的设置里，所以另一个浏览器或清空 profile 后会回到业务语言。
- 运行详情还没有汇总 token 用量、花费与产出文件。
- 记忆、沙箱、网络、数据等级、凭据与 agent-to-agent 字段会被持久化，但 runtime 尚未执行；编辑器中标注了哪些字段会在运行时生效。
- 任务板、审批、A2A 传输与记忆视图尚未实现。
- 会话创建会离开 robot 页面进入工作区会话；创建成功后那行工具卡的「打开机器人」是回去的入口。
