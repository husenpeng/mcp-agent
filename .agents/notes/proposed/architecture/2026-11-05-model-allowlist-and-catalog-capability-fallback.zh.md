# Agent Note: 模型允许清单与跨提供方能力回退

Status: proposed

[English](2026-11-05-model-allowlist-and-catalog-capability-fallback.md) | 中文

## Problem

自定义网关路由不是 pi-ai 的 catalog provider。在此变更之前，它的 Claude 模型会回退到路由级的 `contextWindow` 和 `maxTokens` 猜测值（1M/128k），不继承任何 catalog 兼容块，并要求部署逐项写出推理与容量字段。结果是一个正确的模型运行在错误的窗口上，并且没有 Anthropic 缓存标记；OpenAI 兼容路径把整段历史都按未缓存输入计费，尽管厂商模型支持提示缓存。

同样的自由度让选择失去治理。路由接受所有已配置模型，因此“只允许本地列表加近半年发布模型”的部署没有共享位置表达这件事。在一个界面隐藏模型，也仍然留下直接请求和手动配置不受保护。

## Proposal

### 按规范模型 id 回退能力

自定义路由在折叠网关前缀、版本号中的点，以及日期/版本后缀之后，用每个声明的模型 id 查询第一方 catalog 条目。容量、模态和 `promptCache` 在模型条目未覆盖时来自厂商条目；兼容性与推理元数据只在路由使用厂商协议时继承，因为改接协议后的线上开关具有协议特异性。路由保留自己的协议、端点和凭据。pi-ai 已提供的路由以自身目录为准；其未列出的 id 不会借用其他提供方的能力。family 映射把继承限制在厂商自己的提供方，避免转售商的输出上限变成模型能力。

当匹配到的是 OpenAI 兼容路由上的 Anthropic Messages 模型时，适配器会在路由或模型未点名该开关时应用 `cacheControlFormat: anthropic`。若网关拒绝该标记，可用 `cacheRetention: none` 让该路由退出。

### 带发布日期清单的允许清单

`@tomato/llm-pi-ai` 的 `modelPolicy` 是默认拒绝的允许清单。`local` 是部署当前的本地模型列表，是快照而不是已配置路由的实时视图，因此之后的配置编辑不能扩大它。`releaseDates` 以 `provider/model` 为键记录 ISO 日期，放行所有日期不早于 `recentSince` 的模型，无需第二份列表。`recent` 保留为没有清单条目时的显式日期补充。格式错误的键、日期，或没有下界的日期清单会在加载时失败。

适配器列举所有已配置模型，但用 `blockedReason` 标记被拒绝的组合；catalog 投影携带该字段，输入框渲染带本地化文案的禁用行。`modelAvailable` 拒绝被拦截的选择，`prepareCall`/`stream` 在提供方 I/O 之前抛出 `MODEL_NOT_ALLOWED`，因此手动配置的被拦截模型无法到达网络。

## Alternatives considered

- **把能力修正留给逐路由 YAML。** 每个部署都要为每个模型重述容量、缓存格式和推理，新的 2026 模型会继续沿用旧猜测，直到有人发现。catalog 已经携带这些事实；把它们复制到每个 profile 正是本变更要消除的漂移。
- **过滤 `listModels` 并隐藏被拦截模型。** 隐藏让选择器干净，但用户看不到已配置模型为何消失，手动选择仍然需要单独的守卫。保留带原因的行让策略可检查。
- **在适配器里硬编码发布日期。** 发布数据变化比包快，且与提供方相关。配置清单让适配器不携带会过期的厂商日历；未来的发布 feed 可以生成清单而不是改代码。
- **在请求时跨协议回退。** 把失败的原生调用重试到 OpenAI 兼容路由可能重复计费或重复提供方副作用，并掩盖原生探测本应报告的问题。协议选择仍是配置决定；探测先报告可行性。

## Acceptance criteria

- 点名第一方模型 id 的自定义路由继承其容量、模态和提示缓存行为；显式条目字段优先。
- 同协议的自定义路由继承厂商兼容块，包括会话中更新；协议改接不继承。
- OpenAI 兼容自定义路由上的 Anthropic catalog 模型会收到 `cacheControlFormat: anthropic`，除非显式配置。
- 启用的策略放行 `local` 成员和日期不早于 `recentSince` 的模型；其他每个已配置模型都带 `blockedReason`，在选择器中禁用，被 `modelAvailable` 拒绝，并在任何提供方请求之前以 `MODEL_NOT_ALLOWED` 让 `prepareCall`/`stream` 失败。
- 省略或禁用策略时适配器不受限制；启用但列表为空且没有日期时拒绝所有模型。

## Risks

- **缓存标记只是建议。** 网关可能接受 `cache_control` 却不执行。只有实际观测到 `cacheReadTokens` 才能证明缓存；验证失败的路由需要原生 `/v1/messages` 协议，而不是换一种标记形状。
- **发布清单是外部数据。** 日期可能错误、过期，或使用与 relay 不同的模型 id。错误日期会静默改变允许清单；清单需要负责人和刷新路径。
- **允许清单只覆盖 `@tomato/llm-pi-ai` 路由。** `@tomato/llm-deepseek` 路由不在范围内；同时通过两个适配器提供模型的部署需要更高层的策略。
- **`local` 是快照。** 之后把模型加入提供方列表会被拦截，直到更新允许清单。这是预期的失败方式，但需要配置工作流而不是隐式刷新。
- **被拦截行是可见的。** 策略不再静默；原本期待隐藏模型的部署现在会看到禁用行，并需要解释原因文案。
- **能力继承是提示，不是保证。** 网关可能以不同量化或输出上限重新导出模型；厂商匹配可能高估端点实际提供的能力。显式字段仍是纠正手段。
