# Agent Note：机器人资源的文件夹式弹出层

Status: implemented

[English](2026-11-06-robot-resource-pickers.md) | 中文

## 问题

高级规格编辑器把技能、MCP 服务器与工作区根目录放在同一个内联菜单里。技能行只给名称，藏起来源文件夹；MCP 行只给服务器名，看不出它由部署配置；工作区根目录则是一个以 chip 保存的路径加自由输入框。三个字段被同样对待，但它们并不相同：工作区根目录是文件系统路径，技能是有来源文件夹的名称，MCP 服务器则是部署配置的名称，机器人规格里没有它的文件夹。

## 决定

只有工作区根目录是真正的路径。技能选项现在通过可选的 `RobotCapabilityOption.path` 携带来源文件夹（技能指令文件所在目录），工作区选项在 `path` 里重复自己的目录，MCP 服务器省略该字段，因为它的配置——包括 stdio 服务器的 `cwd`——属于部署。

技能、MCP 服务器与工作区根目录改为打开模态的 `ResourcePicker`，不再使用菜单。技能行显示来源文件夹；MCP 行列出已配置服务器，并说明工作目录由部署决定；工作区行显示绝对路径。其余列表字段保留内联菜单，所有字段都保留自由输入。

工作区选择器增加「浏览文件夹…」，通过 `uiWorkspace.listDirectory` 打开 `FolderPicker`。该服务使用 browse 后端的列目录原语；当部署提供 native directory-picker 能力时，列目录被拒绝就是改用 `uiWorkspace.pickDirectory()` 打开系统选择器的信号。被取代的扫描通过 `AbortController` 中止，一个打开沿只启动一次扫描，因此 StrictMode 的第二次 setup 不会打开第二个选择器。

## 考虑过的替代方案

**让三个字段都浏览文件系统。** 技能与 MCP 服务器在规格里存的是名称，不是路径。选中一个文件夹无法写进规格，MCP 服务器也没有可选的文件夹；要支持它需要新增规格字段与运行时语义，而不是换一个选择器。

**复用工作区目录流的槽位。** browse 与 native 选择器包填充的是工作区浏览器和 hero 选择器拥有的两个洞，没有向其他功能暴露 factory 或服务。机器人编辑器要复用就必须新增跨包槽位契约。调用既有的 `uiWorkspace` 目录方法只保留一个所有者，也不新增槽位。

**始终打开系统选择器。** `uiWorkspace.pickDirectory()` 是 native 后端的动词；远程与进程内部署提供 browse 能力，根本没有系统选择器。先尝试列目录也让正确界面自己出现，而不需要客户端探测能力。

## 后果

- `RobotCapabilityOption.path` 是新增的 wire 字段。既有读取方会忽略它；对只有名称的值，Host 会省略它。
- MCP 工作目录仍属于部署配置。选择器会说明这一点，而不是暗示存在按机器人设置的目录。
- 文件夹选择器负责列出、导航与显示隐藏文件夹；新建文件夹仍属于工作区浏览器，这里暂不提供。
- 测试覆盖资源选择器、文件夹选择器的 browse 与 native 路径、被取代的结算、编辑器接线以及扩展后的能力投影；各包 README 与机器人子系统页在两种语言下都描述了模态选择器。
