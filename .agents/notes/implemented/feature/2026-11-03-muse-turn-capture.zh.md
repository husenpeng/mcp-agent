# Agent Note: Muse 回合后的候选捕捉

Status: implemented

[English](2026-11-03-muse-turn-capture.md) | 中文

## 问题

只有模型在回合中决定调用 `memory_write` 时，记忆才会增长。模型会忘记这个决定，而人很少按需重复一条长期规则，于是最该有内容的地方反而空着。Hindsight 会自动摄取对话，但它的抽取在服务端按自己的队列运行，可能需要几分钟才可召回。muse 需要一个本地版本，并且绝不让未经确认的猜测进入后续会话。

## 决定

`capture`（默认关闭）为每个结束的回合增加一次辅助请求。请求只读取该回合中人的文本消息，每条前面带上事件 seq，并受 `captureMaxInputBytes` 约束；助手文本与合成上下文从不进入请求，因此模型无法强化自己的说法。回复被解析为至多三条候选，每条都必须通过三道门才能存储：引用必须能在该回合的消息中找到；同一范围内不得已有相同身份的记录；`duplicates()` 不得发现近似重复。`MemoryError` 会丢弃该条候选，其他存储失败则向上传播。

每条被存储的候选都是 `status: 'candidate'`、`pinned: false`，因此在人执行 `/memory confirm` 之前，它不会进入搜索、快照或项目索引。引用匹配同时提供 `source.userMessageSeq`，也就是 `/memory show` 打印的证据。

请求及其结果以 `plugin:tool-memory/turn-capture` 写入会话：路由、准确的系统文本、首尾输入 seq、token 上限，以及 `stored`（ids）、`empty`、`skipped`（原因）或 `failed`（原因）之一。记录 seq 范围而不是文本，使模型可见输入可重建，同时不把对话复制进日志。

接线是可选的：只有当 `@tomato/session-query` 挂载时监听器才注册，路由取自该回合自己的最后一个 `request/header`。没有人的文本、没有路由、或无人登录的回合不会发送任何请求。请求在 `turn/end` 之后作为被跟踪的操作运行，因此不会延迟回合；释放会中止它并等待收敛。

## 考虑过的替代方案

**直接激活捕捉到的记忆。** 一条未经人确认的模型转述会进入之后每个会话，这正是候选状态要防的失败；捕捉会成为未经核验上下文中最大的一类。

**把助手文本也当作证据。** 那会让模型引用自己，把自己早先的猜测写进长期记忆。在 muse 的其他所有入口，人的话都是唯一证据。

**在 `agent/turn-stopping` 捕捉。** 该事件之后回合仍可被 steer，转录会不完整，而且请求会与循环争抢延迟。

**把完整请求交换存进记录。** 输入可以由记录的 seq 范围推出，复制它只会让会话日志重复对话文本。

**默认开启捕捉。** 无论用户是否说了持久内容，它每个回合都会花一次请求；实验层不应仅仅因为更新组合包就改变某个 profile 的成本结构。

**允许模型不引用就写入。** 引用匹配只做一次包含判断，却把候选绑定在人真正说过的话上。

## 后果

- 捕捉减少的是遗漏，而不是判断上的重复：被捕捉的陈述仍需要人确认，近似重复与身份两道门只能拒绝词面上的重复。
- 没有记录请求头的回合不会捕捉任何内容；未挂载 `@tomato/session-query` 的组合即使打开开关也会保持休眠。
- 该插件记录是实验性持久化类型，因此持久化目录会变化；不认识该类型的读取器会保留并跳过它。
- 请求是模型可见的，因此包 README 的捕捉小节、两种语言的 README、两种语言的配置目录，以及工具目录的写入列表都会变化。
- 覆盖率保持 100%。[组合包真实组合测试](../../../../packages/experimental/muse-bundle/tests/bundle.spec.ts) 在打开 `capture` 的情况下启动随包发布的行，断言候选被存储、记录被写入，以及该候选不出现在后续会话的快照中。本层补完的层次记录在[关系与健康笔记](2026-11-03-muse-memory-relations-and-health.zh.md)，它复用的门禁记录在[重复提示笔记](2026-11-03-muse-memory-duplicate-hints.zh.md)。
